Achillea Web

Plateforme communautaire pour la scene competitive d'Inazuma Eleven: Victory Road. Application Angular 21 moderne avec standalone components, Signals et httpResource.

Angular 21 TypeScript 5.9 PrimeNG 21 Tailwind CSS 4 Socket.io 4

Presentation

Achillea Web est le frontend de la plateforme Achillea, une application Angular 21 moderne destinee a la communaute competitive d'Inazuma Eleven: Victory Road.

Elle repose sur une architecture 100% standalone components (sans NgModule), le systeme de Signals d'Angular pour la reactivite, et l'API experimentale httpResource pour le chargement declaratif des donnees.

Fonctionnalites principales

Clans

Creation (wizard multi-etapes), gestion des membres, invitations, candidatures, distinctions, organigramme hierarchique

Tournois

Creation complete, inscriptions, seeding, brackets (single/double elimination, round robin), report et validation des scores

Ranked

Statistiques Elo 1v1 et 2v2, historique de matchs, classement par paliers

Profils

Profil joueur enrichi (stats ranked + interclan), profil clan public

Notifications

Temps reel via WebSocket (Socket.io), apercu dans le header

Administration

Dashboard admin pour moderation et validation d'organisations

Reactivite et state management

L'application utilise exclusivement les Signals Angular pour la gestion d'etat — aucun store externe (NgRx, Akita, etc.).

Signals

Les Signals sont des valeurs reactives qui notifient automatiquement les consommateurs lors des changements :

TypeScript 
// Signal modifiable
user = signal<UserDTO | undefined>(undefined);

// Signal derive (recalcule automatiquement)
userHasClan = computed(() => !!this.user()?.clan);

// Effet (s'execute quand les signaux dependants changent)
effect(() => {
  const resp = this.clansResource.value();
  if (resp) this._accumulated.set(resp.data);
});

httpResource (API experimentale Angular 19.2+)

httpResource est un wrapper reactif autour de HttpClient qui expose le statut et la reponse sous forme de Signals :

TypeScript 
// Requete reactive : se relance automatiquement quand clanId() change
readonly clanFromRoute = httpResource<ClanDTO>(
  () => this.clanId() ? { url: `/api/clans/${this.clanId()}` } : undefined
);

// Acces aux donnees via Signals
const clan = this.clanFromRoute.value();       // Donnees
const loading = this.clanFromRoute.isLoading(); // Chargement en cours
const error = this.clanFromRoute.error();       // Erreur eventuelle
HTML (Template) 
<!-- Utilisation dans les templates -->
@if (clan.hasValue()) {
  <clan-card [clan]="clan.value()" />
} @else if (clan.isLoading()) {
  <p-progressSpinner />
} @else if (clan.error()) {
  <p-message severity="error" text="Erreur de chargement" />
}

Pattern de pagination infinie

TypeScript 
// Accumulation des pages via effet
private _accumulated = signal<ClanDTO[]>([]);

readonly clansResource = httpResource<Paginated<ClanDTO>>(
  () => this.page() !== 0 ? ({
    url: '/api/clans',
    params: { page: this.page(), pagination: this.limit() }
  }) : undefined
);

effect(() => {
  const resp = this.clansResource.value();
  if (!resp) return;
  this._accumulated.update(prev => [...prev, ...resp.data]);
});

clans = computed(() => this._accumulated());

Authentification et securite

Flux d'authentification (Discord OAuth2)

┌─────────────┐ ┌─────────────────┐ ┌─────────────┐ │ Utilisateur │────>│ GET /auth/discord│────>│ Discord │ │ (Frontend) │ │ (Backend) │ │ OAuth2 │ └──────────────┘ └─────────────────┘ └──────┬──────┘ │ ┌──────────────────────────────────────────┘ │ Code d'autorisation v ┌─────────────────┐ ┌──────────────┐ │ Backend echange │────>│ Cookie JWT │ │ code → token │ │ HTTP-only │ └─────────────────┘ └──────┬───────┘ │ ┌────────────────────────┘ v ┌─────────────────┐ ┌──────────────┐ │ GET /auth/me │────>│ Profil user │ │ (avec cookie) │ │ charge │ └─────────────────┘ └──────────────┘
  1. Clic sur "Se connecter" → redirection GET /api/auth/discord?state=returnUrl
  2. Discord authentifie l'utilisateur et redirige avec un code
  3. Le backend echange le code, cree/met a jour l'utilisateur, signe un JWT
  4. Le JWT est stocke dans un cookie HTTP-only (securise)
  5. Le frontend charge le profil via GET /api/auth/me
  6. WebSocket se connecte automatiquement pour les notifications

Toutes les requetes API incluent withCredentials: true pour transmettre le cookie de session.

Les notifications sont gerees via Socket.io avec le namespace dedie /notifications :

TypeScript 
// NotificationSocketService
private socket = io('/notifications', {
  withCredentials: true,
  transports: ['websocket', 'polling']  // WebSocket prioritaire, polling en fallback
});

// Ecoute des notifications
this.socket.on('notification', (data: NotificationModel) => {
  this._userNotifications.update(prev => [data, ...prev]);
